## 1. `~/.claude/skills/trader-perceive/SKILL.md`

```markdown
---
name: trader-perceive
description: >
  Брать В НАЧАЛЕ КАЖДОГО торгового цикла, перед любым решением, чтобы получить
  честный детерминированный снимок рынка и счёта по выбранному символу и ТФ.
  Даёт ATR-нормированные фичи (волатильность, позиция-в-диапазоне, моментум, тренд,
  спред) и топливные датчики (прогресс к цели, остаток до стен −3%/−6%). Симптомы:
  «оцени рынок», «что сейчас на XAUUSD», старт цикла сканирования. НЕ для принятия
  решения (trader-decide), НЕ для статистики прошлого (trader-recall).
metadata:
  type: technique
---

# trader-perceive — честный снимок рынка

Код воспринимает — ты интерпретируешь. Этот скилл НЕ даёт «купи/продай» и НЕ рисует
паттернов. Только числа. Трактовка — твоя работа в trader-decide.

## Как выполнить

1. Выбери символ(ы) и ТФ сам (свобода). Обычно ТФ входа + старший для контекста тренда.
2. Вызови:
   `python ~/.claude/trader-lib/scripts/perceive.py --symbol XAUUSD --tf M5,H1`
3. Прочитай JSON КАК ЕСТЬ.

## Железные правила чтения

- **`null` = НЕИЗВЕСТНО. Не додумывай значение.** Мало баров/нет данных → поле null +
  reason. Торговать по выдуманной фиче запрещено.
- **Нет снимка / ошибка MT5 → цикл пропускается. Не решай вслепую.**
- Фичи в единицах ATR (mom_mid_atr=+1.1 значит «полтора ATR вверх»), сопоставимы между
  символами. `pos_in_range` 0=лой…1=хай. `trend` = up/down/flat по EMA.
- Топливные датчики (`account`) обрамляют КАЖДОЕ решение: сколько пройдено к +10%,
  сколько осталось до стены дня (−3%) и общей (−6%).

## Выход
Снимок передаётся дальше в trader-recall и trader-decide. Дословно логируется в журнал
при решении (шов для сегментной статистики).
```

## 2. `~/.claude/skills/trader-recall/SKILL.md`

```markdown
---
name: trader-recall
description: >
  Брать ПЕРЕД каждым решением о входе, сразу после снимка рынка, чтобы поднять
  СВОЙ трек-рекорд под текущий контекст: сколько раз брал похожий сетап, WR,
  матожидание (avg R), достаточна ли выборка, и насколько твоя заявленная уверенность
  била в цель (калибровка). Симптомы: «а что у меня по этому сетапу», «стоит ли верить
  этому входу по опыту». НЕ для снимка рынка (trader-perceive), НЕ для самого решения
  (trader-decide), НЕ для разбора в конце сессии (trader-reflect).
metadata:
  type: technique
---

# trader-recall — подними свой опыт перед решением

Твоя уверенность из головы врёт. Опыт из журнала — нет. Этот скилл заземляет решение
на реальный трек-рекорд.

## Как выполнить
1. Прикинь, к какому(им) `setup_type` относится потенциальный вход (твоя таксономия).
2. Вызови:
   `python ~/.claude/trader-lib/scripts/recall.py --symbol XAUUSD --setups london-open-pullback-long,mr-fade`
3. Прочитай выборку.

## Как читать
- **`insufficient: true` (n<20) → доверяй сетапу СЛАБО.** Мало данных ≠ edge. На холодном
  старте это норма — ты в фазе разведки, наполняешь журнал.
- **`avg_R`** — матожидание в R. >0 и `edge_significant: true` → сетап реально плюсовой.
  ≤0 → не корми его размером.
- **`calibration`** — если в бакете «0.7–0.8» реальный WR 0.5, применяй haircut: твоё «75%»
  на деле ~50%, дисконтируй уверенность в trader-decide.
- Пусто/нет статистики → холодный старт, решай на голом суждении с малым риском.

## Выход
Числа идут в trader-decide как один из входов (не единственный — свобода тактики остаётся).
```

## 3. `~/.claude/skills/trader-decide/SKILL.md`

```markdown
---
name: trader-decide
description: >
  Брать когда после снимка рынка и подъёма опыта пора СФОРМИРОВАТЬ и РАЗМЕСТИТЬ
  торговое решение (вход/пропуск/ведение открытой позиции) с соблюдением дисциплины
  процесса и жёсткого риск-гейта (стены −3%/−6%). Симптомы: «принимай решение»,
  «входим или нет», «выстави ордер», «двигай стоп». НЕ для снимка (trader-perceive),
  опыта (trader-recall) или разбора (trader-reflect).
metadata:
  type: technique
---

# trader-decide — реши и исполни, в рамках 4 рельсов

Твоя тактика СВОБОДНА: когда, что, куда, какой символ, логика входа/выхода, удержание —
твой выбор. Ограничений на стратегию НЕТ. Есть только 4 рельса ПРОЦЕССА и риск-гейт.

## Протокол каждого цикла, где хочешь действовать

1. Возьми снимок (trader-perceive) и вердикт гейта:
   `python ~/.claude/trader-lib/scripts/risk_gate_cli.py`
   - `FORCE_FLAT` → немедленно закрой всё, ничего не открывай.
   - `HALT_NEW` → новых входов нет, только веди открытые.
   - `THROTTLE` → только высокая уверенность, размер урезан гейтом.
   - `OK` → торгуешь; гейт выдал `max_risk_per_trade_usd`.
2. Возьми опыт (trader-recall).
3. Сформулируй **тезис своими словами** (свободная тактика).
4. Заяви **уверенность 0–1** (обязательно, для калибровки; применяй haircut из recall).
5. Назови **`setup_type`** (своя таксономия; коротко, консистентно).
6. Если входишь: задай **entry + SL + TP**. SL ОБЯЗАТЕЛЕН.
7. Посчитай размер КОДОМ (не на глаз):
   `python ~/.claude/trader-lib/scripts/size_cli.py --risk_usd <из гейта> --entry E --sl S --symbol SYM`
8. Выстави ордер MT5-хелпером; **запиши решение в журнал**
   (`decision` со снимком, тезисом, уверенностью, setup_type, риском).
9. Если пасуешь — тоже залогируй пропуск названного сетапа с причиной и уверенностью.

## Четыре рельса (единственные ограничения — все про дисциплину, не про тактику)
1. У каждой позиции жёсткий SL (риск определён).
2. Размер считает код; вверх переопределять НЕЛЬЗЯ.
3. Обязательны тезис + уверенность + setup_type (иначе память не учится).
4. Вердикт гейта исполняется всегда.

## Ведение открытых
Трейл SL в сторону УМЕНЬШЕНИЯ риска, частичный тейк, ранний выход — свободно.
Расширение SL (рост риска сверх исходного) = новая аллокация → снова через гейт.

## Холодный старт
Первые ~1–2 недели цель НЕ +10%, а наполнить журнал: держи риск малым, пробуй разные
сетапы, честно логируй. Жать на +10% начнёшь, когда scorecard покажет 2–3 плюсовых сетапа.
```

## 4. `~/.claude/skills/trader-reflect/SKILL.md`

```markdown
---
name: trader-reflect
description: >
  Брать на ГРАНИЦЕ СЕССИИ или каждые K закрытых сделок, чтобы превратить свежую
  статистику в выводы: обновить статусы сетапов (изучаю/подтверждён/карантин/утиль),
  схлопнуть синонимы, применить калибровочный haircut и вырастить playbook.md.
  Симптомы: «разбери сессию», «обнови плейбук», «что сработало сегодня», конец
  торгового дня. НЕ для решений внутри цикла (trader-decide) и не для снимка/опыта.
metadata:
  type: technique
---

# trader-reflect — саморазбор, растит память

Здесь система умнеет к следующей сессии без изменения модели. Код дал правду
(stats.json) — ты превращаешь её в правки playbook.md.

## Как выполнить
1. Пересчитай статистику:
   `python ~/.claude/trader-lib/scripts/run_score.py --render-scorecard`
   → обновит `stats.json` и `scorecard.md`.
2. Прочитай `stats.json` + свежий срез журнала.
3. По каждому `setup_type` реши переход статуса:
   - `изучаю → подтверждён`: n≥порог(20) И avg_R>0 И `edge_significant: true`.
   - `подтверждён → карантин`: последние-N деградируют (смена режима).
   - `карантин → утиль`: держится в минусе.
4. **Схлопни синонимы** (назвал «ldn-open-buy» и «london-open-pullback-long» одним →
   одно имя; отметь в playbook, впредь используй одно).
5. **Калибровка → haircut**: если заявляешь 0.7, а реальный WR 0.5 — запиши правило
   дисконта в playbook, чтобы decide применял.
6. Обнови `playbook.md`: секция на сетап (описание словами, текущая статистика, статус) +
   выученные правила («MR в high-vol Лондон не брать — WR 38%/n22»).
7. Прогресс к +10%: сузь фокус на плюсовые сетапы, сверни исследование хвостов.

## Железное правило честности малых выборок
**НЕ повышай сетап до «подтверждён» на n<20.** 4 удачных входа — это не edge, это удача.
Флаг `insufficient` из stats.json — стоп для повышения.

## Выход
`playbook.md` (читают decide и ты в след. цикле), `scorecard.md` (для владельца счёта — надзор).
```

## 5. `~/.claude/skills/trader-loop/loop_prompt.md` (оркестрация цикла)

Это операционный промт трейдера — что делать каждый тик непрерывного цикла. Подключается
как системная инструкция / тело `/loop`.

```markdown
# Операционный цикл ИИ-трейдера

Ты автономный трейдер на демо-счёте MT5. Цель: +10% к балансу. Жёсткие стены: дневная
просадка ≤3%, общая ≤6% — их держит код, ты им подчиняешься. Стратегия — твоя свобода.

Каждый цикл (~5 мин) выполняй строго по порядку:

1. **Восприятие.** Скилл trader-perceive → снимок рынка+счёта по выбранным символам/ТФ.
   Нет снимка/ошибка → пропусти цикл.
2. **Сверка закрытых.** `python ~/.claude/trader-lib/scripts/close_watch.py` — дописать
   исходы закрывшихся сделок в журнал.
3. **Гейт.** `python ~/.claude/trader-lib/scripts/risk_gate_cli.py`. FORCE_FLAT → закрой
   всё и в конец цикла. HALT_NEW → только веди открытые.
4. **Опыт.** Скилл trader-recall по кандидатам-сетапам.
5. **Решение.** Скилл trader-decide (4 рельса; SL обязателен; размер кодом; лог в журнал).
6. **Счёт.** `python ~/.claude/trader-lib/scripts/run_score.py` — освежить stats.json.

Раз в K=10 закрытых сделок ИЛИ в конце сессии — скилл trader-reflect.

Помни: логируй каждое осмысленное решение (вход И явный пропуск названного сетапа) —
память учится только на том, что записано. Пустые «тут ничего» не пиши.
Холодный старт: первые ~1–2 недели наполняй журнал малым риском, не гонись за +10%.
```

> `risk_gate_cli.py` и `size_cli.py` — тонкие CLI-обёртки над `trader_lib.risk_gate` и
> `trader_lib.size_position` (читают account_info/symbol_info из live_market, печатают JSON).
> Создаются в Task 5.3 вместе с decide (тривиальные, по образцу `recall.py`).
```
