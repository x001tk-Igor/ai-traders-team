## Порядок дня

### 1. Директор, 06:30–07:30 UTC

```bash
cd <REPO>
python scripts/bootstrap_env.py --quiet      # ok=false → день не начинается ни у кого
python scripts/director.py scan
```

**Как читать скан.** `stale_market: true` у большинства символов означает, что
рынок ещё не проснулся — числа нерепрезентативны, раздавать по ним мандаты
нельзя. Подожди и повтори.

`tf.H1.costs_R` — издержки при честном стопе `max(минимум по издержкам,
1.5 ATR)`. Годным считается ТФ, где они заняли не больше 80% лимита.

**Стандарт — H1 по всем инструментам.** Не ради единообразия: одинаковый ТФ
позволяет механизму копить n≥20 через весь кластер, а бюджет событий не
вмещает M15.

Серверный день:

python -c "import sys; sys.path.insert(0,'.'); import datetime as dt; from trader_lib.config import load_config; from trader_lib.session import server_day_key; c=load_config('config/trader.config.json'); print(server_day_key(utc_now=dt.datetime.now(dt.timezone.utc), offset_hours=c.risk.server_utc_offset_hours, reset_hour=c.risk.server_day_reset_hour))"

### 3. Спавн трёх трейдеров

Модели: **trend → sonnet**, **fade → opus**, **range → sonnet**.

Промт каждому строится по одному шаблону — ниже отличия. Общая часть:

> Ты — трейдер `<имя>` в команде ИИ-трейдеров. Каталог:
> <REPO>
>
> МАНДАТ: `<инструмент>`, доля 0.33, квота событий 25. Вход по другому
> инструменту гейт отклонит. СТАНДАРТ ТФ: H1.
>
> 1. `python scripts/session_start.py --trader <имя> --model <модель> --profile strong`
> 2. `python scripts/perceive.py --symbol <инструмент> --tf H1`
> 3. Назови режим одной строкой. «Моего сетапа нет» — законный ответ.
> 4. План дня в свой файл (путь через `workspace_path(..., trader='<имя>')`).
>    Стоп обязан стоять ВНЕ шума: не меньше 1.5 ATR H1 за структурой.
> 5. Взведи свои алерты в своём `alerts.json`, все с `"once": true`.
>    Уровни мерь от ЖИВОЙ цены датчика, а не от закрытия бара.
>
> Ордер отправляй только если гейт пропустил и ты сам уверен. Отчёт: режим,
> гипотезы с уровнями, число алертов, расхождения ожидаемого и фактического.

**Специализации (постоянные, не меняются по дням):**

- **`trend`** — трендовое продолжение по подтверждённому ADX. Вход ПО
  направлению, когда ADX содержательно преодолел 20–25 и растёт СВЕЖО.
  Обязательная проверка на остаточность: высокий ADX может быть лагом
  угасающего движения в противоположную сторону.
- **`fade`** — фейд выноса на тонкой книге. Признак: спред ×2.5+ к медиане ПРИ
  низком или падающем ADX. Вход не на пике спреда, а на его распаде — цена
  возвращается, когда книга восстанавливается (для этого есть тип условия
  `spread_normalizes`). **Если H1 идёт против входа — не входить вовсе**, а не
  входить с пониженной уверенностью: оба опровержения гипотезы за неделю
  пришлись ровно на эту конфигурацию.
- **`range`** — границы диапазона. Критерий — связка И: ADX < 25 **И**
  `move_efficiency` < 0.2, проверенные В МОМЕНТ ВХОДА, а не когда сработал
  алерт. Плюс отдельное требование R:R ≥ 1.5 при честном стопе: тесная
  консолидация не обязана давать сделку.

## Риск: почему команда не опаснее одиночки

| | |
|---|---|
| `max_open_positions` | 3 — ровно три трейдера по позиции |
| `max_open_risk_pct` | 1.5% суммарно |
| `per_trade_risk_cap_pct` | 0.5%, статус «изучаю» ×0.2 → **~0.1% на сделку** |
| Стены | −3% день, −6% всего, держит код |

Один трейдер мог бы открыть те же три позиции. Гейт не спрашивает, кто отправил
ордер, — он считает деньги. Фактическая экспозиция понедельника: **~0.3%** при
стене 3%.

Дополнительно команду держат три проверки, которых нет у одиночки: мандат
(чужой инструмент), кластерный потолок (одна позиция на фактор риска), квота
событий.

дал сбоев и не удвоил риск, а не плюс по счёту.

**Главный методический вывод недели, применять с первого решения:** во всех
убыточных сделках, где в тезисе была записана оговорка против него самого

Записанное сомнение — сигнал, а не формальность. Приходится писать «но H1
против» — сделку не брать вовсе.
