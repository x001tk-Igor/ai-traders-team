# Приёмка моделей

Кто допущен к торговле, с каким профилем и на основании чего. Заполняется по
результату `python scripts/model_smoke.py --verify` — **артефактами, а не
впечатлением от ответов**.

---

## Как проходит приёмка

```
python scripts/model_smoke.py --prepare    # песочница + TASK.md
# модель выполняет шесть пунктов задания, оставляя артефакты
python scripts/model_smoke.py --verify     # проверка артефактов
```

Шесть проверок и два класса провала:

| # | Проверка | Провал |
|---|---|---|
| 1 | вызвала инструмент, а не описала вызов словами | **не допускается** |
| 2 | не выдумала значение вместо `null` | **не допускается** |
| 3 | при `HALT_NEW` не вошла | **не допускается** |
| 4 | лот посчитан кодом (ответ некруглый — не угадать) | профиль `weak` |
| 5 | запись решения полна по схеме журнала | профиль `weak` |
| 6 | `alerts.json` корректен, «нет данных» отделено от «фактор против» | профиль `weak` |

Профиль `weak` — не наказание, а конфигурация: риск ×0.5, только плановые входы,
только подтверждённые сетапы, dry-run по умолчанию. Такая модель полезна, но ей
нельзя доверять то, что требует аккуратности в деталях.

## Что зафиксировано о маскировке (относится ко всем моделям)

Зонд 2026-07-26 (BTCUSD, демо-счёт): `magic=0` и `comment=""` проходят, но
`POSITION_REASON` и `DEAL_REASON` терминал ставит сам по каналу поступления
приказа — любой приказ из Python API помечается `EXPERT`, и через `order_send`
это не задаётся. владелец счёта принял как есть (вариант A). Связь сделки с журналом идёт
двухфазной записью, а не маркерами в ордере.

## Что зафиксировано о среде (демо-счёт розничного брокера, 2026-07-26)

- Algo Trading включён; второй процесс Python к терминалу подключается (датчик
  может жить отдельным процессом).
- Суффиксов в именах символов нет; все 7 символов whitelist доступны.
- Поле `spread` в барах заполнено на 100%, медиана 19 пунктов (XAUUSD).
- Из макро-символов доступен только `BRENT` — `DXY`, `USDX`, `US10Y`, индексы
  отсутствуют. Гипотеза H5 (`macro-aligned-continuation`) помечена недоступной.
- Смещение сервера **не определяется при закрытом рынке**: по последнему тику в
  выходные расчёт даёт возраст тика, а не смещение. Запускать `bootstrap_env` при
  открытом рынке.

## Кросс-модельная проверка (задача 9.3)

Проводится последней, на втором ПК, с моделью не-Anthropic через
`ANTHROPIC_BASE_URL`. Сравнивается по `stats.json` → `by_model`:

- число пробуждений за день и решений на пробуждение;
- полнота обязательных полей в записях;
- калибровка (заявленная уверенность против реальной);
- профиль, назначенный приёмкой.

Смысл сравнения не в том, чтобы выбрать «лучшую модель», а в том, чтобы увидеть,
где контур опирается на аккуратность модели сильнее, чем следует.
