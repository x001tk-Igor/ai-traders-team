# Развёртывание ИИ-трейдера — инструкция для Claude Code

**Кому:** экземпляру Claude Code на ПК трейдера (Windows + MT5).
**Что делаешь:** разворачиваешь пакет, проверяешь каждую деталь и запускаешь контур.
**Чем это не является:** списком для галочек. Каждый шаг даёт ответ да/нет; при
«нет» ты останавливаешься и чинишь, а не идёшь дальше.

> ⚠️ **Развёртывание проваливается тихо.** Файл не докопировался, пакет другой
> версии, терминал не залогинен, конфиг поправили по дороге — всё это выглядит
> как «вроде поставилось» и всплывает на первой сделке реальными деньгами.
> Поэтому здесь всё проверяется машинно, а не глазами.

---

## Фаза 0 · Что тебе дали

Папка `trader-deploy-<дата>` с тремя частями:

```
trader-lib\      — пакет: код, тесты, документы, конфиг
skills\          — четыре скилла для Claude Code
trader-state\    — journal.jsonl, playbook.md, telegram.json
```

**Три файла в `trader-state`, а не два — и `playbook.md` здесь не менее важен,
чем журнал.** `journal.jsonl` хранит сырые записи по каждой сделке и
пробуждению; `playbook.md` — это выжимка выводов ПОПЕРЁК событий (механизм
гипотезы, пороги, негативные контроли), которую модель формулирует сама и
которая нигде больше не хранится. Она НЕ восстанавливается из журнала
автоматически: наблюдения в журнале держат рассуждение по каждому событию по
отдельности, playbook — синтез. Забыть его при переносе означает начать
торговую логику заново, сохранив только сырые данные.

`stats.json` и `scorecard.md` при этом переносить необязательно — это
производные, `python scripts\run_score.py` пересчитает их из `journal.jsonl`
на новом месте.

Если чего-то из трёх нет — **останавливайся и скажи владельцу счёта**. Без `trader-lib`
работать нечему; без `skills` ты не найдёшь инструкций; `trader-state` может
отсутствовать, только если история начинается с нуля (уточни явно).

## Фаза 1 · Раскладка по путям

Пути **не произвольные**: скиллы и промт зовут скрипты как
`~/.claude/trader-lib/scripts/...`. Положишь иначе — ни одна команда не найдётся.

```powershell
$c = "$env:USERPROFILE\.claude"
$src = "<путь к папке trader-deploy>"

robocopy "$src\trader-lib" "$c\trader-lib" /E /NFL /NDL /NJH /NJS
robocopy "$src\skills" "$c\skills" /E /NFL /NDL /NJH /NJS
New-Item -ItemType Directory "$c\trader-state\demo-primary" -Force
Copy-Item "$src\trader-state\*" "$c\trader-state\demo-primary\" -Force
```

Должно получиться:

```
C:\Users\<user>\.claude\
├── trader-lib\{config,scripts,trader_lib,tests,docs,prompts}
├── skills\trader-{start,perceive,recall,decide,reflect}\SKILL.md
└── trader-state\demo-primary\{journal.jsonl,playbook.md,telegram.json}
```

## Фаза 2 · Зависимости

```powershell
python --version                                  # нужен 3.10+
pip install MetaTrader5 pandas numpy pytest
```

Разрядность Python и терминала MT5 должна совпадать (обычно 64-бит). При
несовпадении `mt5.initialize()` вернёт `False` без внятной причины — это самая
частая и самая непонятная ошибка на этом шаге.

## Фаза 3 · Проверка развёртывания — одна команда

```powershell
cd $env:USERPROFILE\.claude\trader-lib
python scripts\verify_install.py
```

Скрипт проверяет тринадцать вещей по порядку от фундамента к верху и печатает
таблицу. Разбирай **сверху вниз**: нижние проверки зависят от верхних.

| Проверка | Что значит провал |
|---|---|
| Python, Пакеты, Разрядность | чини по Фазе 2 |
| **Целостность файлов** | контрольные суммы не сошлись — файл не докопировался или изменён. Имена названы поимённо; перекопируй их из комплекта |
| Расположение пакета | лежит не в `~/.claude/trader-lib` — перенеси, иначе модель не найдёт скрипты |
| Скиллы | не попали в `~/.claude/skills` — скопируй |
| Конституция и state_dir | конфиг не читается или папка состояния не создаётся |
| Журнал сделок | файл есть, но не парсится — **не чини руками**, покажи владельцу счёта |
| **Тесты** | должно быть `833 passed`. Красное — СТОП, дальше нельзя |
| MT5: связь | терминал не запущен, не залогинен или разрядность не та |
| MT5: Algo Trading | включи: Сервис → Настройки → Советники |
| Конституция подтверждена | Фаза 4 |
| Модель объявлена | Фаза 5 |

Пока таблица не станет полностью зелёной, к торговле не переходи.

## Фаза 4 · Среда брокера и подтверждение лимитов

```powershell
python scripts\bootstrap_env.py --quiet
```

Ждём `ok: true`. При `false` читай `blocking` — там сказано, что чинить. Частые случаи:

- **смещение сервера не совпадает с конфигом** — впиши названное число в
  `config\trader.config.json` → `risk.server_utc_offset_hours`. Профиль
  намеренно не правит конституцию сам: от смещения зависит граница торгового
  дня, а значит и стена −3%;
- **смещение не определено вовсе** — рынок закрыт. Метод опирается на свежий
  тик; в выходные последняя котировка пятничная. Запусти при открытом рынке;
- **нет символа из whitelist** — у брокера другое имя (суффиксы вроде `.m`).
  Покажи владельцу счёта, конфиг правит он.

Затем — **действие владельца счёта, не твоё**:

```powershell
python scripts\constitution_ack.py            # показать лимиты
python scripts\constitution_ack.py --ack --note "первый запуск на этом ПК"
```

Подтверждая, человек заявляет, что видел лимиты и согласен. **Не выполняй `--ack`
сам без его явного указания в этом разговоре** — смысл механизма именно в том,
что это его решение.

## Фаза 5 · Открытие сеанса

Первая команда каждой сессии — **объяви себя**:

```powershell
python scripts\session_start.py --model <твоё имя> --profile strong
```

Подставь **своё** имя (`claude-opus-5`, `qwen-max`, `glm-4`…), а не то, что
написано в конфиге. Определить модель из кода невозможно: Claude Code не
передаёт её имя дочерним процессам — ты единственная, кто знает точно. Этим
именем подписывается каждая запись журнала, по нему считается твоя калибровка,
и смешать две модели в одном бакете значит испортить статистику обеих без
возможности разделить.

Пока не объявишься, предвходовой гейт не пустит в рынок.

Профиль `strong` — полные права; `weak` (риск ×0.5, только плановые входы,
только подтверждённые сетапы) ставится по результату приёмочного теста:

```powershell
python scripts\model_smoke.py --prepare
# выполни шесть заданий из песочницы (TASK.md), оставив артефакты
python scripts\model_smoke.py --verify
```

## Фаза 6 · Проверка боем на минимальном объёме

Перед настоящей работой прогони цепочку и убедись, что каждое звено живо:

```powershell
python scripts\brief.py --symbols XAUUSD     # orphans пуст, watchdog жив
python scripts\risk_gate_cli.py              # вердикт гейта
python scripts\perceive.py --symbol XAUUSD --tf M5,H1
```

Затем взведи датчик — **один раз за сессию**, инструментом Monitor:

```
Monitor(
  command: "python C:/Users/<user>/.claude/trader-lib/scripts/alert_watch.py",
  description: "торговые алерты: уровни гипотез, стены, позиции",
  persistent: true
)
```

Поставь в `alerts.json` одно заведомо истинное условие и убедись, что строка
пришла тебе уведомлением. Это единственный способ проверить механизм
пробуждения: он работает только внутри живой сессии Claude Code.

**Обязательно ставь `"once": true`** на уровни и триггеры. Алерт без `once`
будит раз в минуту, пока условие истинно, и сжигает дневной лимит (40 событий)
за 40 минут — остаток дня ты глухая.

## Фаза 7 · Рабочий цикл

Дальше работай по `prompts\loop_prompt.md` (скилл `trader-start` доводит до этой
точки сам, если сессию открыли словом «работай»). Коротко:

брифинг → план дня → вооружение датчика **один раз** → работа только по
событиям → на каждом пробуждении одна запись из трёх (вход / осознанный отказ /
наблюдение с рассуждением) → в конце дня `review.py --save` и `trader-reflect`.

## Фаза 8 · Что проверить в конце первого дня

```powershell
python scripts\review.py --save
```

- в новых записях есть `regime`, `model_id`, `planned`, `costs_R`, `session_phase`;
- в `alert_events.jsonl` есть пробуждения, и их за день **не больше 25**;
- полезность пробуждений в отчёте не нулевая (иначе алерты расставлены плохо);
- в Telegram приходили сообщения о входах, выходах и рассуждениях.

## Чего делать НЕЛЬЗЯ

1. **Не правь `config\trader.config.json`, кроме `server_utc_offset_hours` по
   указанию `bootstrap_env`.** Лимиты — решение владельца счёта; любая правка ломает хэш
   конституции и останавливает торговлю до его подтверждения. Это не баг.
2. **Не подтверждай конституцию за человека.**
3. **Не обходи предвходовой гейт**, даже если уверена в сделке. Отказ гейта —
   это ответ, а не препятствие.
4. **Не запускай торговлю при красных тестах.** Восемьсот проверок написаны на
   деньги, а не на стиль.
5. **Не переписывай журнал.** Он append-only; исправление задним числом убивает
   единственный источник правды о том, что происходило.
6. **Не перезапускай датчик ради новых условий** — перепиши `alerts.json`, он
   подхватит сам. Перезапуск теряет состояние бюджета и очередь недоставленного.

## Если что-то не сходится

Сначала `python scripts\verify_install.py --json` — он назовёт проблему точно.
Затем `docs\preflight.md` (полный чеклист) и `docs\constitution.md` (что именно
запрещено системой и почему).

Если проверка целостности нашла изменённые файлы, а ты их не менял — **не чини
сам**: покажи список владельцу счёта. Расхождение может означать, что перенос прошёл не
полностью, и тогда чинить нужно перенос, а не файлы.
