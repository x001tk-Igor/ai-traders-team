# Дизайн: скиллы автономного ИИ-трейдера (MT5, Claude Code)

**Дата:** 2026-07-21
**Статус:** утверждён (брейншторм), готов к плану реализации
**Автор среды:** владелец счёта · сборка скиллов — Claude

---

## 1. Цель и рамки

ИИ-трейдер работает автономно на отдельном ПК: экземпляр **Claude Code** с непрерывным
циклом (`/loop`-стиль), доступ к рынку и исполнение через **MT5 Python API** (пакет
`MetaTrader5`: `copy_rates_*`, `order_send`, `account_info`, `symbol_info`). Символы и
таймфреймы выбирает сам (минимум рамок).

**Бизнес-цель:** заработать **+10% к балансу в короткий срок** на демо-счёте.

**Жёсткие рамки (единственные):**
- дневная просадка **≤ 3%**;
- общая просадка **≤ 6%**.

Больше тактических ограничений нет. Рамки — только на **риск-конверт**, стратегия свободна.

**Ключевой принцип дизайна:** лимиты 3%/6% enforced **детерминированным кодом**, не
суждением модели. Мягкую инструкцию «не теряй больше 3%» модель обходит красивым
обоснованием на убыточной серии. Жёсткий код-гейт — именно то, что *позволяет* отпустить
стратегию на свободу, не рискуя депозитом.

---

## 2. Философия (утверждённый Подход 1 — «Инструментальный агент»)

Скиллы дают агенту **органы чувств, память и дисциплину решения** — и ноль тактического
мнения. Тактику агент выбирает сам, всегда. Рамки только на процесс, никогда на стратегию.
Плейбук стартует пустым — агент растит его сам.

Отвергнутые альтернативы:
- **Дообучение тактиками** — нет датасета «состояние→верное действие»; запекает знание
  статически; усиливает учебниковые паттерны без edge.
- **Стартовый плейбук с засеянными сетапами** — риск заякорить агента на паттернах, у
  которых чаще нет edge. Пусть таксономия вырастет из боевого опыта.
- **Свободный агент + только журнал** — без честной перцепции и дисциплины P&L = шум +
  обоснование, причину не отследить. Это текущее состояние и его failure mode.

**Сквозной шов:** *код воспринимает и считает правду — модель интерпретирует.* Применён
дважды: perceive (код-фичи → модель-трактовка) и score/reflect (код-статистика →
модель-разбор).

## 3. Архитектура

Четыре фокус-скилла + детерминированные скрипты + персистентный стор. Каждый цикл:

```
ЦИКЛ (каждые N минут):
  [скрипт] perceive.py    → snapshot: честные фичи (любой символ/ТФ) + счёт
  [скрипт] risk_gate.py   → вердикт (OK/THROTTLE/HALT_NEW/FORCE_FLAT) + бюджет риска
  [скрипт] close_watch.py → закрылось что-то с прошлого цикла? → дописать outcome в журнал
  if FORCE_FLAT: закрыть всё → лог → в конец цикла
  [СКИЛЛ]  recall         → статистика из журнала под текущий контекст
  [СКИЛЛ]  decide         → тезис + уверенность + SL(обяз.); размер кодом; ордер; запись
  [скрипт] score.py       → освежить stats.json (дёшево, детерминированно)

КОНЕЦ СЕССИИ / каждые K закрытых сделок:
  [СКИЛЛ]  reflect        → рост playbook, переходы статусов, калибровка, scorecard.md
```

**Три типа активов:**
- **Скиллы** (know-how): `perceive` · `recall` · `decide` · `reflect`.
- **Детерминированный код** (в `tools/` скиллов): `perceive.py`, `risk_gate.py`,
  `size_position.py`, `close_watch.py`, `score.py`, MT5-хелперы.
- **Стор** (растущая память, НЕ скилл): `journal.jsonl`, `stats.json`, `playbook.md`,
  `scorecard.md`.

**Напряжение цели и стен и его развязка:** гонка за +10% толкает размер позиции вверх,
угрожая стенам. Риск-на-сделку выводится из **остатка дневного бюджета**, а не из желания
агента: гейт даёт «сегодня можно рискнуть ещё X$», `decide` сайзит внутри. Агент волен в
тактике, арифметика стен — вне его контроля.

## 4. Слой перцепции — `perceive`

Детерминированный `perceive.py` поверх MetaTrader5. Агент передаёт символ + список ТФ,
получает чистый снимок. **Никаких ярлыков** («бычий флаг») и **никаких «купи/продай»** —
только числа и вычислимые дескрипторы режима. Интерпретация — работа `decide`.

Переиспользуются проверенные формулы из `~/.claude/skills/ea-trade-analysis/tools/enrich_context.py`
(уже воспроизводят отчёт QQ), обобщённые на live и любой символ.

**Фичи по каждому запрошенному ТФ:**

| Группа | Фичи |
|--------|------|
| Волатильность | ATR(N) в цене и пипах; ATR-перцентиль (vol относительно своей истории) |
| Диапазон | позиция-в-диапазоне за M баров (0=лой…1=хай); дистанция до свинг-хай/лой |
| Моментум | mom за k баров (коротк/средн/длин) |
| Тренд | знак наклона EMA fast/slow → up/down/flat |
| Микроструктура | текущий спред (в пунктах и ATR); спред-сейчас vs типичный; тик-рейт |
| Время | сессия (Азия/Лондон/NY), час сервера |

Дефолты окон (как в `enrich_context.py`, конфигурируемы): ATR(30), mom за 5/15/30 баров,
позиция-в-диапазоне и свинги за 30 баров, EMA fast/slow 12/26. Считаются на закрытых барах
(не на текущем формирующемся — чтобы фичи не «плавали» внутри бара).

**Три решения дизайна:**
1. **Нормализация по ATR — обязательна.** Сырые пипсы несравнимы между XAUUSD и EURUSD.
   Моментум и дистанции — в единицах ATR → кросс-символьная сопоставимость, статистика
   сетапа копится быстрее. Пип/пункт выводится из `symbol_info` (грабли золота — пип 0.1,
   не 0.01 — закрыты в корне; см. `reference_mt5_gold_pip`).
2. **Анти-галлюцинация — контракт.** Тул **никогда** не возвращает выдуманное значение.
   Мало баров / нет данных → поле = `null` + причина. Модель читает `null` как «неизвестно»,
   не догадывается (принцип `lisa-card-data`).
3. **Снимок логируется дословно в журнал** в момент решения → `recall`/`score` сегментируют
   исход по тем фичам, что были на входе. Шов perceive → journal.

**Блок счёта (TF-независимый) — «топливные датчики» в каждом снимке:**
```
equity, balance, открытые позиции
progress_to_target      → сколько из +10% пройдено
daily_budget_remaining  → $ и % до стены −3% (от equity на старте серверного дня)
total_budget_remaining  → $ и % до стены −6%
```

**Формат выдачи** (JSON, модель читает как есть):
```json
{
  "symbol": "XAUUSD", "ts": "...",
  "tf": {
    "M5":  {"atr_pips": 12.4, "atr_pctile": 0.62, "pos_in_range": 0.18,
            "mom_short_atr": -0.4, "mom_mid_atr": 1.1, "trend": "up",
            "spread_atr": 0.05, "dist_to_high_atr": 1.9, "dist_to_low_atr": 0.3},
    "H1":  {"trend": "up", "atr_pctile": 0.55, "pos_in_range": 0.44}
  },
  "session": "London", "server_hour": 10,
  "account": {"progress_to_target_pct": 3.1,
              "daily_budget_remaining_pct": 2.4,
              "total_budget_remaining_pct": 5.1,
              "open_positions": [...]}
}
```

**Границы юнита:** только читает (copy_rates + account_info + symbol_info) и считает. Не
решает, не ордерит, не пишет в журнал. Тестируется офлайн на исторических барах.

## 5. Стор памяти

Папка по счёту: `~/.claude/trader-state/<account>/`. Журнал — единственный источник правды;
остальное из него выводится.

### 5.1 `journal.jsonl` — append-only, источник правды
Одна строка = одно событие, две связанные записи на сделку (не переписываем, только дописываем).

**Запись-решение** (в момент входа, пишет `decide`):
```json
{"type":"decision","trade_id":"a1b2","ts":"...","symbol":"XAUUSD",
 "features": { "…дословный снимок perceive…" },
 "setup_type":"london-open-pullback-long",
 "thesis":"H1 тренд вверх, M5 откат в 0.18 диапазона, спред тихий",
 "confidence":0.62,
 "action":"buy","entry":2634.1,"sl":2631.0,"tp":2640.0,
 "size":0.12,"risk_usd":38.0,
 "gate_budget_usd":120.0,"gate_verdict":"allowed"}
```

**Запись-исход** (при закрытии, связь по `trade_id`, пишет `close_watch`):
```json
{"type":"outcome","trade_id":"a1b2","close_ts":"...",
 "exit":2639.8,"pips":57,"profit":68.4,
 "R":1.8,"exit_reason":"tp","mfe_R":2.1,"mae_R":-0.4,"duration_min":47}
```

**Решения:**
1. **R-мультипл — атомная единица исхода** (profit ÷ заложенный риск), не пипсы/доллары.
   Нормализует по размеру позиции и символу → пулится, напрямую даёт матожидание.
2. **`setup_type` — свободный текст, агент называет сам.** Таксономия вырастает из агента;
   `reflect` схлопывает синонимы.
3. **Логируем только осмысленные решения** — вход ИЛИ явный пропуск названного сетапа
   (пропуск = трек-рекорд для калибровки). Пустые циклы «тут ничего» не пишем.

### 5.2 `stats.json` — 100% выводимый, пересчитывает `score`
Никогда не редактируется руками. Удали — пересчёт из журнала воспроизводит точно
(защита от дрейфа). Содержит:
- **Общее:** n, WR, матожидание (avg R), PF, суммарный R, макс. серия убытков, текущая DD.
- **По `setup_type`:** n / WR / avg R / последние-N + флаг `insufficient` при `n<20`. Читает `recall`.
- **Сегменты:** по символу, сессии, бакетам фич (pos_in_range, trend, atr-перцентиль) —
  как `analyze_stats.py`.
- **Калибровка:** заявленная confidence vs реальный WR по бакетам → ошибка → haircut.
- **Бейзлайн/значимость:** bootstrap-CI на avg R (пересекает 0?) + сравнение с always-in.

### 5.3 `playbook.md` — агент растит сам через `reflect`
Читаемо человеком и агентом. Секция на каждый `setup_type`: описание словами агента,
текущая статистика (из `stats.json`), статус (`изучаю` / `подтверждён` / `на карантине` /
`в утиль`). Плюс выученные правила и haircut калибровки. Стартует почти пустым.

### 5.4 Владение (один писатель на файл)
`decide` → дописывает решение · `close_watch` → дописывает исход · `score` →
пересчитывает `stats.json` + рендерит `scorecard.md` · `reflect` → правит `playbook.md`.

## 6. Решение `decide` + риск-гейт

### 6.1 `risk_gate.py` — детерминированный, не обсуждается

**Определения (дефолты; конфигурируемы одной строкой, под конкретную prop-фирму подгоняются):**
- **Дневной лимит:** 3% от equity на старте серверного дня (00:00 брокера), **по equity**
  (плавающий убыток считается).
- **Общий лимит:** 6% от стартового баланса (статичный baseline, не трейлинг).
- **Буфер безопасности:** форс-флэт срабатывает раньше стены (напр. 2.7% дневных), чтобы
  проскальзывание/спред на закрывающем ордере не пробили жёсткий лимит.
- **День считается по серверному времени брокера** (сервер в UTC, не Екб — грабля среды).

**Вердикт каждый цикл:**
```
OK          → торговля разрешена, выдаёт max_risk_per_trade_usd
THROTTLE    → <1% дневного бюджета → только high-conviction, урезанный размер
HALT_NEW    → бюджет исчерпан → новых входов нет, только веду открытые
FORCE_FLAT  → пробой близко/достигнут → закрыть всё немедленно
```

**Механизм развязки цели и стен:**
```
max_risk_per_trade = remaining_daily_budget / K      (K≈3 — запас на серию стопов)
                     capped by 1% equity
```
Даже 3 полных стопа подряд не достают до стены −3%.

**Fail-closed:** ошибка гейта / не читается счёт → дефолт `HALT_NEW`. Никогда не fail-open
в торговлю.

### 6.2 `size_position.py` — детерминированный сайзинг
Дано entry, дистанция SL, `max_risk_per_trade_usd` → лот такой, что
(дистанция SL × стоимость пункта × лот) = risk_usd, с учётом contract size, min/max lot,
lot step. Агент задаёт entry+SL, размер считает код, вверх переопределить нельзя.

### 6.3 `decide` — протокол (дисциплина процесса, работа модели)
Каждый цикл, где агент хочет действовать:
1. Читает `perceive` + вердикт гейта. `HALT_NEW`/`FORCE_FLAT` → подчиняется.
   `THROTTLE` → только высокая уверенность, урезанный размер.
2. Читает `recall`.
3. Формулирует тезис своими словами — тактика свободна.
4. Заявляет уверенность (0–1) — обязательно, для калибровки.
5. Называет `setup_type`.
6. Действие: entry + SL + TP. **SL обязателен** — без него риск не определён, гейт не
   сайзит → сделки нет.
7. Размер через `size_position.py` внутри бюджета гейта — код, не модель.
8. Ставит ордер, дописывает решение в журнал. Если пасует — логирует пропуск с
   причиной+уверенностью.

**Четыре рельса процесса — ВСЕ ограничения агента, тактических рельсов ноль:**
1. У каждой позиции жёсткий SL.
2. Размер считает код, вверх не переопределить.
3. Обязательны тезис + уверенность + `setup_type`.
4. Вердикт гейта исполняется.

**Управление открытыми:** трейл SL в сторону уменьшения риска, частичный тейк, ранний
выход — свободно. Расширение SL (рост риска сверх исходного) = новая аллокация, проходит
через гейт.

Всё остальное (когда, что, куда, символ, логика входа/выхода, время удержания) — свободно.

## 7. Обратная связь — `score` + `reflect`

### 7.1 `score.py` — детерминированный, 0 токенов
Джойнит decision+outcome по `trade_id`, пересчитывает `stats.json` (каждый цикл, дёшево).
`scorecard.md` рендерится на ритме `reflect` (конец сессии / K сделок), не каждый цикл —
это человекочитаемый артефакт для надзора, не машинный. Ключевое:
- **Матожидание по `setup_type`** = avg R, с `n` и флагом `insufficient` при `n<20`.
- **Калибровка:** бакеты по уверенности → реальный WR → ошибка → haircut.
- **Бейзлайн/значимость:** отличимо ли матожидание от нуля при этом `n` (bootstrap-CI) +
  сравнение с always-in. Ответ на «мастерство или везение?».
- **Сегменты:** WR и avg R по бакетам фич.

`scorecard.md` — человекочитаемый срез для владельца счёта: equity-кривая vs бейзлайн,
матожидание±CI, калибровка, прогресс к +10%.

### 7.2 `reflect` — саморазбор модели, растит `playbook.md`
Ритм: граница сессии / день / каждые K закрытых сделок — НЕ каждый цикл.
1. Читает свежий `stats.json` + срез журнала.
2. Переходы статуса по `setup_type`:
   - `изучаю → подтверждён`: `n≥порог` И матожидание>0 И проходит флаг значимости.
   - `подтверждён → карантин`: последние-N деградируют.
   - `карантин → в утиль`: держится в минусе.
3. Схлопывает синонимы сетапов.
4. Пишет выученные правила и haircut калибровки в `playbook.md`.
5. Прогресс к +10%: сузить фокус на плюсовые сетапы, прекратить исследование хвостов.

**Петля замыкается:** `reflect` пишет → следующий цикл `recall` читает `stats.json`,
`decide` читает `playbook.md` (утиль не берёт, haircut применяет).

**Честность малых выборок:** `score` флажит `insufficient`, `reflect` **не имеет права**
повышать сетап на `n<порог`. Защита от самообмана на демо.

## 8. Холодный старт (двухфазный)

Первые недели `recall` почти везде `insufficient`. «+10% в короткий срок» на нулевой
памяти = азарт. Честная последовательность:
- **Фаза 1 (≈1–2 нед): разведка.** Цель — наполнить журнал: гейт держит риск-на-сделку на
  полу (мелкий размер), уверенность сильно дисконтируется, агент пробует разные сетапы.
- **Фаза 2: давление на edge.** Когда `scorecard` показывает 2–3 сетапа с плюсовым
  матожиданием и достаточным `n` — концентрируем размер на них, жмём к +10%.

Переключение ведёт `scorecard`, не календарь. Можно жать сразу — но это гэмблинг, и гейт
тогда просто не даёт взорвать счёт. Стены 3%/6% держат в любом случае.

## 9. Развёртывание

- Скиллы → `<ПК-трейдера>/.claude/skills/` (`perceive`/`recall`/`decide`/`reflect`).
- Стор → `~/.claude/trader-state/<account>/` (создаётся на первом запуске).
- Loop-промт того ПК кодирует последовательность цикла (§3).
- Один конфиг: лимиты 3/6, цель 10, правило старта дня, K, буфер, ритм reflect, порог `n`.
- Зависимости на том ПК: `MetaTrader5`, pandas, numpy.
- **Сборка и юнит-тесты — на этом ПК** (perceive/score/gate тестируются офлайн на
  фикстурах, live MT5 не требуется), пакуем → **владелец счёта разворачивает, валидируем в live.**

---

## 10. Обработка ошибок (fail-closed)

- MT5 недоступен / нет данных → perceive отдаёт explicit error, цикл **пропускается**. Не
  торгуем вслепую, снимок не фабрикуем.
- **Гейт fail-closed:** ошибка / не читается счёт → `HALT_NEW`.
- Ордер отклонён (реквот/маржа/рынок закрыт) → лог; запись в журнал только по
  **подтверждённому филлу** из MT5, не по намерению.
- `close_watch` сверяет исходы с **историей MT5** (источник правды), не с задуманными TP/SL.
- День — по серверному времени брокера. Запись в журнал — атомарный append.

## 11. Тестирование

- perceive/score/gate/сайзинг — детерминированы → юнит-тесты на фикстурах. Регрессия:
  perceive воспроизводит числа `enrich_context` на данных QQ.
- Гейт — тесты границ: буфер 2.7%, `HALT` при бюджете 0, и **property-тест: никакая серия
  убытков за день не пробивает 3%** при правиле сайзинга.
- decide/reflect — детерминированные части (SL обязателен, кап размера, форма записи;
  переходы статусов на синтетическом журнале).
- **E2E dry-run:** прогон исторических баров через всю петлю в демо/paper без реальных
  ордеров → санити журнала+статы+scorecard; гейт не пробивается на adversarial-сериях.

## 12. Открытые параметры конфига (дефолты заданы, подтвердить при развёртывании)

| Параметр | Дефолт | Заметка |
|----------|--------|---------|
| Дневной лимит | 3% equity от старта дня | под prop-фирму подгоняется |
| Общий лимит | 6% от стартового баланса, статичный | трейлинг — опция |
| Буфер форс-флэта | 2.7% (0.3% запас) | против слиппеджа |
| K (делитель бюджета) | 3 | запас на серию стопов |
| Кап риска на сделку | 1% equity | верхняя граница |
| Порог `n` для «подтверждён» | 20 | честность малых выборок |
| Ритм `reflect` | конец сессии / K сделок | K уточнить |
| Старт дня | 00:00 сервера брокера | UTC, не Екб |
